[code-00012] To find the least-played (or most-played) song in the Spotify song library:
1. Use `show_song_library` with pagination to get all songs (each object contains `song_id`).
2. For each song, call `show_song(song_id=song_id)` to retrieve `play_count` (a float).
3. Find the minimum (or maximum) play_count and return the corresponding `title`.
Example snippet:
```python
all_songs = []
page_index = 0
while True:
    page = apis.spotify.show_song_library(access_token=token, page_index=page_index, page_limit=20)
    if not page:
        break
    all_songs.extend(page)
    page_index += 1
song_play_counts = []
for song in all_songs:
    details = apis.spotify.show_song(song_id=song['song_id'])
    song_play_counts.append({'title': details['title'], 'play_count': details['play_count']})
least_played = min(song_play_counts, key=lambda x: x['play_count'])
answer = least_played['title']
```

Example snippet:
```python
all_recs = []

        break

from collections import Counter
artist_counts = Counter()
for rec in all_recs:
```

[code-00040] To find the oldest (or newest) released song across all Spotify libraries (song, album, playlist):
1. Collect all unique song IDs from the song library using `show_song_library` with pagination.
2. Collect all unique song IDs from the album library using `show_album_library` and extracting `song_ids` from each album.
3. Collect all unique song IDs from the playlist library: use `show_playlist_library` with pagination, then for each playlist call `show_playlist` to get its `songs` array, and extract the `id` of each song.
4. For each unique song ID, call `show_song` to retrieve the `release_date` field.
5. Use ISO 8601 string comparison (lexicographic) to find the minimum (oldest) or maximum (newest) release_date.
6. Return the corresponding `title`.
Example snippet:
```python
all_song_ids = set()
# Song library
page_index = 0
while True:
    page = apis.spotify.show_song_library(access_token=token, page_index=page_index, page_limit=20)
    if not page:
        break
    for song in page:
        all_song_ids.add(song['song_id'])
    page_index += 1
# Album library
page_index = 0
while True:
    page = apis.spotify.show_album_library(access_token=token, page_index=page_index, page_limit=20)
    if not page:
        break
    for album in page:
        for song_id in album['song_ids']:
            all_song_ids.add(song_id)
    page_index += 1
# Playlist library
page_index = 0
while True:
    page = apis.spotify.show_playlist_library(access_token=token, page_index=page_index, page_limit=20)
    if not page:
        break
    for playlist in page:
        pl_details = apis.spotify.show_playlist(playlist_id=playlist['playlist_id'], access_token=token)
        for song in pl_details['songs']:
            all_song_ids.add(song['id'])
    page_index += 1
# Find oldest
oldest_song = None
oldest_date = None
for song_id in all_song_ids:
    details = apis.spotify.show_song(song_id=song_id)
    if oldest_date is None or details['release_date'] < oldest_date:
        oldest_date = details['release_date']
        oldest_song = details
answer = oldest_song['title']
```

## COMMON MISTAKES AND CORRECT STRATEGIES

[cms-00013] Do not confuse 'song library' with 'playlist library'. When the task asks for songs in the user's library (e.g., 'least-played song in my Spotify song library'), use `show_song_library` (not `show_playlist_library`). The song library contains individual songs, while playlists are collections. Using the wrong API will lead to incorrect results.
[cms-00016] Do not confuse 'album library' with 'song library' or 'playlist library'. When the task asks for songs in the user's album library (e.g., 'most-played song in my Spotify album library'), use `show_album_library` to get albums and their song_ids, then query individual songs. Using `show_song_library` or `show_playlist_library` will return songs from the wrong collection and lead to incorrect results.
[cms-00019] Avoid syntax errors and API name typos: Always double-check that all string literals (including f-strings) are properly closed with matching quotes and braces. When calling an API, ensure the function name is spelled exactly as shown in the API documentation (e.g., 'review_song' not 'view_song'). A quick visual scan before executing can prevent wasted steps.
[cms-00020] Do not mix explanatory text with code in code blocks. Every line in a code block must be valid Python code. If you need to explain what the code does, add comments using `#` at the start of the line, or write the explanation outside the code block. Including uncommented text inside a code block will cause a syntax error and the entire block will fail to execute.
[cms-00031] When retrieving transactions for multiple users (e.g., coworkers), ensure you paginate through all pages for each user. Do not assume a single page (e.g., page_limit=20) captures all transactions. Use a while True loop with page_index incremented until an empty page is returned.
[cms-00041] Do not assume that `show_playlist_library` returns song IDs directly. The response from `show_playlist_library` contains only playlist metadata (e.g., playlist_id, title). To get the list of songs in a playlist, you must call `show_playlist` for each playlist and extract the `songs` array. The existing code snippet [code-00038] is incorrect in stating that song_ids are directly available from the playlist library response; always use `show_playlist` to retrieve song IDs.
[cms-00044] Do not assume that a user found via email search on Venmo is automatically a friend. The `friends_since` field indicates friendship status; if it is `None`, you are not friends. Sending a payment request to a non-friend may fail or be inappropriate. Always check this field and, if needed, add the user as a friend before proceeding.

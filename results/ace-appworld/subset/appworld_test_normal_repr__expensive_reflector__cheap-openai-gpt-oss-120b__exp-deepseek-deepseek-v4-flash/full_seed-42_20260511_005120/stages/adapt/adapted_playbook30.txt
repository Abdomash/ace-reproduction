## COMMON MISTAKES AND CORRECT STRATEGIES

[cms-00010] Do **not** assume the first result from a search API is the correct one. Verify by examining all results, especially when the task description is ambiguous or when multiple notes share similar keywords.
[cms-00013] Do **not** rely on a single date‑range query to detect prior Venmo payments. Payments can be sent on any date, so using a fixed `min_created_at`/`max_created_at` may miss them. Always verify per‑recipient with the `user_email` filter and paginate through all results.
[cms-00015] [cms-00014] Do **not** hardcode calendar values (year, month, day) for relative time queries. Instead, dynamically calculate them using `datetime.now()` (or equivalent) and format them as required by the API (YYYY‑MM‑DD). This prevents mismatches when the environment's current date differs from the assumed static value.
[cms-00016] [cms-00016] Do **not** assume that a single page of results from `search_contacts` contains all relevant contacts. The `search_contacts` API is paginated (default page_limit=5). Always loop over `page_index` until an empty page is returned to collect the complete set of contacts, especially when filtering by relationship (e.g., `relationship='coworker'`).
[cms-00018] [cms-00017] When a task asks for "sent or received" amounts, the request is ambiguous. Default to providing both totals (sent and received) in a clear structure (e.g., a dict) unless the wording explicitly requests a combined figure. If unsure, include both values and a brief note explaining the interpretation.

## VERIFICATION CHECKLIST

[vc-00011] When verifying whether friends have already paid via Venmo, loop over **all pages** of `show_transactions` (using `page_index` and optionally `page_limit`) for each friend to ensure no transaction is missed before deciding to send a payment request.
[vc-00012] When verifying Venmo payments for a list of people, query `show_transactions` separately for each person's email using the `user_email` filter and `direction='received'`. Loop over all pages (`page_index`) without applying narrow `min_created_at`/`max_created_at` date ranges, because payments may have occurred on any date. Only consider a person as having paid if a transaction is found in any page of their filtered results.
[vc-00017] [vc-00013] Before aggregating Venmo transaction amounts for coworkers, verify that the coworker list retrieved via `phone.search_contacts` has been fully paginated. Loop over `page_index` (and optionally increase `page_limit` up to the allowed maximum) until no more contacts are returned, then proceed with the financial calculations.
[vc-00020] [vc-00018] Verify that the final answer's format matches the task's phrasing: if the task asks for a single monetary amount, return a single number (rounded to two decimals); if it asks for separate sent/received values, return a dictionary with keys "total_sent" and "total_received". Ensure rounding is applied consistently.
